# Shadowfetch DrKonqi pickup correction

KDE DrKonqi 6.6.5's login pickup processor waits forever after an empty journal
scan. Its upstream 30-minute runtime guard then reports a failed user service.
The processor can also finish before all pending batches have been scanned.
This package builds the pinned, signature-verified upstream processor with a
small correction and selects it through a pickup-only `ExecStart` drop-in.

Pickup completes at the journal end, including the empty case. Per-dump
`finished` signals do not interrupt a pickup batch scan. A synchronous error
flag prevents queued successful completion from overriding a recorded failure;
negative journal reads are reported as errors rather than mistaken for EOF.
The socket protocol and synchronous write loop remain upstream code: each
record is serialized and written before the scan advances. Completion does
not wait for crash-report windows to close; their socket-activated services
have independent lifetimes. The vendor runtime guard, ordering and launcher
socket remain in place. Debian's processor binary and per-crash service are
never replaced. Removing this package restores the upstream pickup command.

The full upstream archive, its detached signature, the KDE-published release
key and the downstream patch are included in the Debian source package.
The build checks the exact archive SHA256 and uses no network. Build on Debian
13 with `debhelper`, `cmake`, `g++`, `pkg-config`, `patch`, `qt6-base-dev` and
`libsystemd-dev`, `python3` and `bubblewrap`; runtime dependencies are generated by `dh_shlibdeps`.
The helper uses Qt Core/Network and libsystemd, with no full Plasma build chain.

Run behavior validation only inside a disposable rootless Podman container
with those build dependencies and Python 3, or through the provided runner
which uses Bubblewrap on a normal Linux builder. It uses private `/run/user/1000`
and `/tmp` fixtures and never touches a desktop user's crash collector:

```
cmake -S . -B build-test -DENABLE_BEHAVIOR_TESTS=ON -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build-test -j2
python3 tests/run-tests.py --build-dir build-test
```

The checks run actual upstream and patched Qt executables. A deterministic
libsystemd ABI fixture supplies journal records; real Unix sequenced-packet
sockets receive and validate the resulting JSON. Cases cover empty scans,
pending records, 257 records across multiple batches, missing cores, socket
failures, journal failures and unchanged non-pickup behavior. Two additional
checks use the real libsystemd journal, including the full one-minute settle
delay. A final installed-image check must still validate the actual Plasma
unit/socket and retain clean service state beyond the old 30-minute deadline.

When rebasing DrKonqi, revalidate the native pickup socket protocol, journal
fields, upstream service ordering and runtime guard. The 4.0 ISO acceptance
gate checks the tested upstream package version 6.6.5-3; this package does not
place a global APT hold or pin on future KDE updates.
